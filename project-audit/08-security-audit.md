## 2. In-Depth Security Findings

### SEC-01: Potential Stored Cross-Site Scripting (XSS) in Reviews Component
- **Location:** [index.html#L6756-L6765](file:///c:/Users/livem/Downloads/Compressed/QRBD/index.html#L6756)
- **Code Snippet:**
```javascript
g.innerHTML = d.reviews.map(function(v){
  return '<div class="rv-card">' +
    '<div class="rv-head"><div class="rv-name">' + v.name + '</div>...</div>' +
    '<div class="rv-txt">“' + v.text + '”</div>' +
    '<div class="rv-foot">' + v.city + '</div></div>';
}).join('');
```
- **Vulnerability Analysis:**
  The `d.reviews` array returned by `/api/reviews` is directly interpolated into an HTML string and injected into the DOM using `.innerHTML`. If the backend review submission endpoint accepts raw strings without strict server-side HTML entity escaping, an attacker could craft a review containing malicious script payloads (e.g. `<img src=x onerror=alert(document.cookie)>`).
- **Potential Impact:**
  Execution of arbitrary client-side code in visitors' browser contexts, potentially accessing `localStorage` tokens or spoofing phishing prompts.
- **Recommended Remediation:**
  Implement a lightweight client-side HTML escaping utility prior to string interpolation:
```javascript
function escapeHtml(str) {
  return String(str || '').replace(/[&<>"']/g, function(s) {
    return ({ '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;' })[s];
  });
}
// Use: escapeHtml(v.name), escapeHtml(v.text), escapeHtml(v.city)
```

### SEC-02: Content Security Policy `unsafe-inline` Relaxation
- **Location:** [deploy/staging_server.py#L14-L23](file:///c:/Users/livem/Downloads/Compressed/QRBD/deploy/staging_server.py#L14)
- **Code Snippet:**
```python
CSP = ("default-src 'self'; script-src 'self' 'unsafe-inline' https://checkout.razorpay.com "
       "https://cdnjs.cloudflare.com https://*.cashfree.com; style-src 'self' 'unsafe-inline' "
       "https://fonts.googleapis.com; ...")
```
- **Vulnerability Analysis:**
  To accommodate the single-file architecture of [index.html](file:///c:/Users/livem/Downloads/Compressed/QRBD/index.html) (which contains 12 inline script tags and 10 style blocks), the CSP explicitly specifies `'unsafe-inline'` for `script-src` and `style-src`. This neutralizes CSP's primary defense against script injection attacks.
- **Recommended Remediation:**
  1. Extract inline scripts into external static `.js` files or compute cryptographic hashes (`sha256-...`) for each approved `<script>` block.
  2. Implement per-request dynamic CSP nonces (`nonce-{random}`) generated by Cloudflare Workers or the backend edge server.

### SEC-03: Attribute Breakout Risk in Logo Injection
- **Location:** [index.html#L5404](file:///c:/Users/livem/Downloads/Compressed/QRBD/index.html#L5404)
- **Code Snippet:**
```javascript
if (bw) bw.innerHTML = '<img src="' + cfg.logoUrl + '" alt="legacy brand" style="height:38px;max-width:180px;object-fit:contain;">';
```
- **Vulnerability Analysis:**
  If the superadmin settings stored in `/api/homepage-config` are tampered with or contain double-quotes, an attacker could break out of the `src` attribute (e.g. `logoUrl = '" onerror="alert(1)'`).
- **Recommended Remediation:**
  Create DOM elements safely using standard DOM APIs:
```javascript
if (bw && cfg.logoUrl) {
  var img = document.createElement('img');
  img.src = encodeURI(cfg.logoUrl);
  img.alt = 'legacy brand';
  img.style.cssText = 'height:38px;max-width:180px;object-fit:contain;';
  bw.replaceChildren(img);
}
```

### SEC-05: Domain Anti-Theft Canary Architecture
- **Location:** [index.html#L1-L15](file:///c:/Users/livem/Downloads/Compressed/QRBD/index.html#L1) (Script 0)
- **Allowlist Implemented:**
```javascript
var h = location.hostname;
if (h === "localhost" || h === "127.0.0.1" || h === "[::1]" ||
    /(^|\.)localhost$/.test(h) || /(^|\.)legacy-domain$/.test(h) ||

```
- **Security Assessment:**
